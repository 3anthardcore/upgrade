## Локальный воспроизводимый запуск

Требуется Node.js 24, npm и Git. Эксплуатационный путь — отдельный Linux runtime; Windows/WSL2 используются для разработки. Не заменяйте системный Node других приложений.

```sh
npm ci
npx playwright install chromium
npm run check
npm test
npm run test:e2e
npm run demo:fixture
```

Для полного набора PHP-проверок задайте абсолютный `UPGRADE_PHP_BIN` (PHP 8.3); на Windows также `UPGRADE_PHP_EXT_DIR`. Без PHP соответствующие тесты могут сообщить SKIP: это не PASS. Последний сохранённый общий прогон перед r16: **419/419 unit/integration и25/25 E2E,0SKIP**, `npm run check` PASS. Новые незавершённые изменения проверяются отдельно. Эти числа не заменяют независимую приёмку изменений или native испытание. Версии и области проверки — в [совместимости](docs/compatibility.md).

`demo:fixture` запускает синтетический источник `127.0.0.1:8787`, сохраняет снимки, модель, пакет и отчёт, затем закрывает источник. По умолчанию результат находится в `var/projects/fixture-demo-v2/`: `state/upgrade.db`, `source/`, `artifacts/`, `releases/`, `reports/index.html`. Повтор использует сохранённые данные. Отчёт явно оставляет Битрикс **NOT_RUN** для этого fixture.

## Путь от ссылки до демо

Полная последовательность, роли пользователей ОС, профили и контрольные точки: **[runbook внутреннего демо](docs/runbooks/internal-demo.md)**.

```sh
npm run upgrade -- doctor --json
npm run upgrade -- init --source https://example.com/ --id sample-company
npm run upgrade -- plan --project sample-company
npm run upgrade -- run --project sample-company --until demo-ready
npm run upgrade -- status --project sample-company --json
npm run upgrade -- report --project sample-company
```

Обычный `run` пока заканчивается контролируемым `BLOCKED` с отчётом: он не выполняет provisioning, native import и включение HTTP-сценариев автоматически. `doctor` проверяет локальные возможности, но не заменяет аттестацию настроенного целевого Битрикс. Доступны отдельные `crawl`, `extract`, `build`, `import --dry-run`, `verify`, `report`, `package`. Обычный `import --apply` остаётся заблокированным; реальная отдельная команда — `target apply` с закреплённым профилем, пакетом, backup receipt и приватным журналом.

Если автоматический HTTP-обход получил challenge, источник остаётся PAUSED. Разрешённые оператором браузерные наблюдения можно отдельно принять через `operator-capture ingest`, извлечь `operator model --all-observed` и собрать `operator build --all-observed`. Это не снимает source access block и не доказывает полноту сайта. Встроенный браузер Codex используется оператором; его внутренние инструменты не являются внешним API Upgrade. Программный агентный адаптер использует документированный Codex CLI.

Для собственного fixture допускается только точное `--fixture-origin http://127.0.0.1:8787`. В обычном crawl проверяются DNS/IP, redirects и бюджеты; исходные POST, WebSocket и service workers запрещены. `--browser` использует отдельный контекст и контролируемый загрузчик, но не доказывает изоляцию ОС для произвольного враждебного сайта. Challenge не обходится автоматически.

## Продолжение и восстановление

```sh
npm run upgrade -- pause --project sample-company
npm run upgrade -- resume --project sample-company
npm run upgrade -- status --project sample-company --json
npm run upgrade -- backup --project sample-company --to /safe/path/sample-backup
npm run upgrade -- restore --from /safe/path/sample-backup --to /safe/path/restored-project
```

Повтор начинают с сохранённого состояния и проверки артефактов. Бюджет и история сохраняются, просроченное владение не оживляется. Неизвестный исход публикации или импорта сначала сверяется с назначением. `resume` не означает разрешение обхода защиты источника; повтор HTTP после access block требует отдельного явного подтверждения и сохраняет прежние пределы.

Эти `backup`/`restore` относятся к **состоянию Upgrade**. SQL, файлы CMS и приватное состояние демо требуют отдельной копии и испытания восстановления: [runbook](docs/runbooks/internal-demo.md#восстановление-и-откат). Закрытие чата не удаляет состояние и не обещает продолжение работы без запущенного процесса.

## Реальная команда агентов

```sh
npm run test:agents
```

Отдельный проверенный smoke запускает два настоящих `codex exec` одновременно, сохраняет task IDs, события, usage, SHA-256 и структурированные результаты. Нужны установленный и авторизованный Codex CLI, доступная модель и бюджет; необязательные настройки — `UPGRADE_CODEX_BIN`, `UPGRADE_CODEX_MODEL`. Не переносите секреты локальной авторизации на сервер автоматически. Денежная стоимость без тарифных данных — `UNAVAILABLE`.

Роли из `agents/` загружаются адаптером. Автоматический профиль анализирует переданные данные без инструментов; интерактивная реализация кода выполняется отдельными сохранёнными задачами в непересекающихся областях. Это не универсальный автономный shell-write worker. Протокол: `task create/claim/heartbeat/submit/review`, `artifact add`, `inspect`, `agents --file dispatch.json`; см. [адаптер](docs/codex-adapter.md). Автор результата не принимает его сам; агенты не редактируют SQLite.

## Границы реализации

- URL независимы от CMS и Bitrix ID; значимые query, порядок, повторы и пустые значения сохраняются. Полнота считается от исходного реестра, включая ошибки и отложенные адреса.
- Тексты и факты снабжены источниками. Неоднозначные цены, наличие, единицы, ограничения количества и варианты не выдумываются. Неизвестный итог в демо — `null` / «требует уточнения».
- Собственные модуль, шаблон, компоненты и router находятся в `/local`. Native импорт через API создаёт управляемый контент; полноценная миграция каталога offers/SKU, остатков и бизнес-правил не заявлена.
- Демо-заявки и оформление сохраняются только локально как синтетические записи; реальные письма, заказы, платежи и состояние «оплачено/отправлено» не создаются.
- Business установлен, технический администратор создан и API-аутентификация проверена исторически. Штатная браузерная админка, редактирование с проверкой конфликта и удалённая активация лицензии — отдельные незакрытые проверки.
- Клиентские данные, snapshots, БД, runtime binaries, лицензии и секреты исключены из Git. Production-переключение и публичный SaaS не реализованы этим демо-контуром.
