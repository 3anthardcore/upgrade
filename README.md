# Upgrade

Внутренний CLI для исследуемого и проверяемого переноса публичного сайта на «1С-Битрикс: Управление сайтом». Состояние, задачи, версии артефактов и проверки сохраняются на диске. Язык отчётов — русский.

**Текущая версия 0.1 — работающий исследовательский и упаковочный контур, не завершённая система миграции.** Есть настоящий HTTP/Chromium crawl, модель фактов, точные маршруты, SQLite-оркестратор, реальный Codex CLI адаптер, собственный PHP-модуль/шаблон/импортёр и пакет развёртывания. Полный импорт и админка настоящего Битрикс, работающий магазин, три пилота и production-переключение ещё не подтверждены. `DEMO_READY` не выставляется.

## Быстрый воспроизводимый запуск

Требуется Node.js 24, npm и Git. Основной эксплуатационный путь — Linux; на Windows используйте WSL2 с отдельным Node 24. Windows также проверен как среда разработки. Не заменяйте системный Node, от которого зависят другие приложения.

```sh
npm ci
npx playwright install chromium
npm run check
npm test
npm run test:e2e
npm run demo:fixture
```

Последняя команда запускает синтетический источник на `127.0.0.1:8787`, сохраняет снимки, извлекает данные и создаёт проверяемый пакет Битрикс. Источник закрывается после запуска. Результаты остаются в `var/projects/fixture-demo-v2/`: `state/upgrade.db`, `source/`, `artifacts/`, `releases/`, `reports/index.html`. Отчёт намеренно сообщает о непроведённой интеграции Битрикс и неподдержанных функциях. Повторный запуск использует сохранённые снимки.

`npm test` требует установленный Chromium для реального browser-теста. PHP-проверка автоматически пропускается с явным SKIP, если `UPGRADE_PHP_BIN` отсутствует. Для полного локального набора задайте путь к PHP 8.3+, а для Windows также `UPGRADE_PHP_EXT_DIR`. Это валидатор пакета и синтаксис, не доказательство работы CMS.

## Проект по ссылке

```sh
npm run upgrade -- doctor --json
npm run upgrade -- init --source https://example.com/ --id sample-company
npm run upgrade -- plan --project sample-company
npm run upgrade -- run --project sample-company --until demo-ready
npm run upgrade -- status --project sample-company --json
npm run upgrade -- report --project sample-company --format html
```

Без настроенного Битрикс `run` заканчивается `BLOCKED`, exit 3, с отчётом и готовым к независимой проверке пакетом. HTML-preview не подменяет целевой сайт. `--browser` включает свежий браузерный контекст и перехват запросов через защищённый HTTP-загрузчик; это не доказательство полноценной изоляции уровня ОС. Для произвольных враждебных источников нужен отдельный Linux-контейнер/пользователь без секретов.

Только для своего локального синтетического источника передавайте точный `--fixture-origin http://127.0.0.1:8787`. Это исключение нельзя использовать для production/private networks. DNS/IP проверяются на каждом соединении, GET и перенаправления ограничены; исходные POST/формы, WebSocket, service workers запрещены. Неизвестные CMS не отклоняются: используются публичные HTML/DOM.

Доступные отдельные этапы: `crawl`, `extract`, `build`, `import --dry-run`, `verify`, `report`, `package`. Они используют то же владение запуском. `import --apply --environment demo` пока возвращает конкретный блокер ненастроенного target gateway; настоящий PHP CLI импортёр применяется по [инструкции Битрикс](docs/bitrix.md). `deploy` без полного production-профиля и доказательств прекращается до изменений.

## Продолжение и восстановление

```sh
npm run upgrade -- pause --project sample-company
npm run upgrade -- resume --project sample-company
npm run upgrade -- run --project sample-company --until demo-ready
npm run upgrade -- backup --project sample-company --to /safe/path/sample-backup
npm run upgrade -- restore --from /safe/path/sample-backup --to /safe/path/restored-project
```

`resume` валидирует артефакты, сохраняет бюджет и историю. Истёкшие leases получают новое fencing-владение; поздний исполнитель не может записать результат. Неизвестные затраты резервируются консервативно. Сборка использует хеши контента, маршрутов, дизайна и собственного кода. Повреждённый пакет не принимается даже при подмене его self-declared hashes.

Backup/restore выше относится к состоянию **Upgrade**. База и файлы Битрикс восстанавливаются отдельно; см. `infra/backup/` и [runbook](docs/bitrix.md). Закрытие чата не удаляет состояние, но не обещает продолжение работы. Отдельный запущенный worker имеет собственный deadline; отмена запуска передаётся диспетчером активным процессам.

## Реальные агенты

```sh
npm run test:agents
```

Команда запускает два настоящих `codex exec` одновременно, получает JSON Schema outputs, сохраняет task IDs/events/SHA-256 и принимает результаты отдельным детерминированным проверяющим. Нужны установленный/авторизованный Codex CLI и доступная модель; можно задать `UPGRADE_CODEX_BIN` и `UPGRADE_CODEX_MODEL`. Секреты CLI не копируются на сервер. Измеряется usage, денежная стоимость при отсутствии тарифных данных обозначается `UNAVAILABLE`.

Роли из `agents/` действительно загружаются адаптером. Текущий профиль автоматических агентов — чтение переданных данных, **без инструментов**; он подходит для классификации/анализа. Создание кода ведётся интерактивной командой Codex в непересекающихся областях с регистрацией результатов. Автоматический агент с shell-write правами намеренно не выдаётся за реализованный профиль.

API ядра и CLI: `task create/claim/heartbeat/submit/review`, `artifact add`, `inspect`, `agents --file dispatch.json`. Пример dispatch и протокол — [документация адаптера](docs/codex-adapter.md). Worker не редактирует SQLite: используются методы ядра. Локальный CLI предполагает одного доверенного оператора; это не многопользовательская граница безопасности.

## Границы фактов и готовности

- URL хранится независимо от CMS, Битрикс ID и `CODE`; сохраняются регистр, слеши, `%2F`, расширения, пустые/повторные query. Неизвестные параметры сохраняются.
- Полнота считается по неизменяемому исходному scope, включая ошибки и недоступные URL. Удалить неудачную страницу из знаменателя нельзя.
- Тексты, товары, предложения, наблюдения цен и evidence разделены. Неизвестные цена/наличие остаются неизвестными. Один SKU не объединяет разные товары.
- Пакет Битрикс использует собственный `/local` код и поддерживаемые API. Текущий target — редактируемый снимок контента; полноценные catalog offers, поисковые/фильтровые правила и commerce ещё требуют реализации и испытаний.
- Демо не отправляет настоящие заявки/заказы/платежи. Обнаруженная кнопка остаётся `UNVERIFIED`, пока нет сценария и теста.
- Клиентские данные, БД, snapshots, binaries, лицензии и секреты исключены из Git.
