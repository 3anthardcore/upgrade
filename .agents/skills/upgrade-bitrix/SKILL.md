# Целевой Битрикс

Прочитай `docs/data-contracts.md`, `docs/compatibility.md` и актуальную документацию `bitrix/importer/cli.php`. Исполняемый сборщик — `packages/bitrix-adapter/index.ts`; исходники назначения находятся в `bitrix/`.

```bash
npm run upgrade -- build --project ID
npm run upgrade -- import --project ID --dry-run
```

Полученный профиль `editable-content-snapshot` предназначен для контента. Product не означает настроенный торговый каталог: предложения, цены, остатки, фильтры и commerce имеют отдельные блокеры. Проверяй `manifest.json`, blockers, warnings и `runtime_verification`.

Установка использует только собственные `/local`-модуль, компоненты и шаблон, документированные API Битрикс. Конфликт исходного пути с `/bitrix`, `/local`, `/upload` или реальным файлом — блокер для маршрута, не разрешение молча поменять URL.

Для фактического запуска нужны лицензированный дистрибутив, отдельная БД, проверенные образы по digest и закрытое демо. `bash infra/provisioning/preflight.sh` проверяет конфигурацию, но не доказывает безопасность запущенного Битрикс. Сеть, почта, агенты и события должны быть изолированы до первого bootstrap клона. Без реального импорта, административного редактирования и HTTP-проверок ставь NOT_RUN.
