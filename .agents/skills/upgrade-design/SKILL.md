# Дизайн из фактов

Используй принятый `content-model.json`, feature matrix и ограничения. Роль `agents/designer.md` действительно загружается `CodexAdapter`; подробный исполняемый контракт — `docs/codex-adapter.md`.

Создай JSON задачи с `role: designer`, input artifact IDs, бюджетом, критериями и непересекающимися `allowed_paths`; зарегистрируй до запуска:

```bash
npm run upgrade -- task create --project ID --file task.json
npm run upgrade -- agents --project ID --file dispatch.json
```

`dispatch.json` — массив `{taskId, model, workspace, prompt, resultSchema}`; укажи доступную модель, рабочую директорию и JSON Schema. Текущий профиль не предоставляет модели инструменты. Результат сохраняется как предложение и остаётся VALIDATING до независимой проверки. Не передавай секреты или активный код источника в инструкциях.

Проверяющий сопоставляет факты, контент, длинные тексты, отсутствие изображения, состояния форм, клавиатуру и 360 px. Токены пакета находятся в `data/design-tokens.json`, собственный шаблон — `bitrix/local/templates/upgrade`. Автоматическое применение предложенного агентом дизайна к CSS ещё не подключено: изменения шаблона делает исполнитель в своей области, затем `build --project ID`. Скриншоты и браузерные проверки на настоящем Битрикс обязательны; новый цвет или HTML-preview не равны готовому дизайну сайта.
