# Явная сборка всех операторских наблюдений

Задача `operator-multipage-v1`, run `run-3dc0ebd4-5200-4ae8-9e91-3be4f6ace3ca`, вход `art-bcc1e5c0-3336-4baa-b0b1-c255728b7e4a` / SHA-256 `35e031ad3dc206075007a621d2cebe13dd2c6cc8166bbee78a3068a4bcbfc12a`. Этот документ дополняет первоначальную одностраничную реализацию в `docs/operator-model-cli.md`: ограничение «ровно одна страница» относится к legacy-режиму, а не к новому явному выбору всех наблюдений.

```sh
npm run upgrade -- operator model --project PROJECT \
  --capture CAPTURE_ID --manifest-sha256 MANIFEST_SHA256 --all-observed

npm run upgrade -- operator build --project PROJECT \
  --capture CAPTURE_ID --manifest-sha256 MANIFEST_SHA256 \
  --model MODEL_ID --all-observed

npm run upgrade -- report --project PROJECT
```

Обе команды читают только принятый COMMITTED capture и его неизменяемые артефакты. Сеть и целевая БД не используются. `--all-observed` — флаг без значения, несовместимый с `--page`. При нескольких наблюдениях отсутствие явного выбора отклоняется. Старый выбор `operator model --page ABSOLUTE_URL` и последующий `operator build --model MODEL_ID` сохраняются. Смешивание режима модели и сборки отклоняется до записи сборки.

## Привязка и совместимость

| Выбор          | `operator_binding`                                                          | Hash domain модели / сборки               |
| -------------- | --------------------------------------------------------------------------- | ----------------------------------------- |
| Одна страница  | прежняя `schema_version: 1`, `selected_source_url`                          | `operator-model-v1` / `operator-build-v1` |
| Все наблюдения | `schema_version: 2`, `selection_mode: ALL_OBSERVED`, `selected_source_urls` | `operator-model-v2` / `operator-build-v2` |

Список v2 — точное отсортированное множество source URL всех наблюдений принятого capture. Document URL, ненаблюдавшиеся inventory URL и последующие crawl не подменяют его. Гибридная привязка v1/v2 и v2, выдающая подмножество за ALL_OBSERVED, отклоняются. Все прежние пины capture, manifest, result artifact, source artifact и access block сохраняются. Reporter проверяет оба формата и сверяет список с принятым capture, а не только со счётчиком модели.

Hash модели включает binding и fingerprint её реализации; hash сборки — ID модели, пины трёх выходов, fingerprint builder и design tokens. Формулы v1 не изменены. Проверка исторической модели использует её сохранённый code SHA, позволяя собрать ранее принятую модель новым builder. Обновление кода создаёт новые производные IDs и пакеты по прежнему правилу fingerprint; не переписывает старые sealed artifacts. Повтор при одинаковом коде, входах и выборе возвращает прежние IDs и проверяет байты. Legacy и ALL_OBSERVED могут сосуществовать в одном Store и отчёте.

## Полнота и отказ при пропуске

Модель содержит по одной сущности для каждого выбранного source URL. Перед сборкой проверяются точное множество сущностей, маршрутов и привязка entity→URL. Хотя бы один конфликтующий или запрещённый путь блокирует всю сборку выбранного множества; он не исчезает из результата молча. Сохраняются исходные request target и значимые query, включая порядок, повторы, пустые значения, регистр и percent encoding.

`scope.inventory` остаётся полным принятым реестром, `known_url_count` не уменьшается до количества наблюдений. Например, fixture с 3 наблюдениями и 25 известными URL даёт 3 запланированных маршрута и 22 unresolved. Неизвестная полная величина сайта остаётся `UNKNOWN`, источнику сохраняются `PAUSED` и active access block, производным артефактам — `PARTIAL`. Даже если наблюдения охватят весь известный реестр, это не доказывает полный размер сайта или рабочие функции.

Шапка собственного пакета показывает число выбранных страниц из известного реестра, а его scope JSON сохраняет весь реестр. Репорт отдельно показывает выбранные URLs, режим, число сущностей, запланированные и нерешённые маршруты. Blockers пакета, включая недостающие файлы, по-прежнему запрещают рекомендацию импорта. `NOT_READY` не повышается, source HTTP 200 и target import/HTTP не объявляются проверенными. Неопределённые цены и наличие не нормализуются этой правкой.

## Восстановление и проверка

Механизм PENDING→COMMITTED и проверка неизвестного результата сохранены: до публикации закрепляются вход и SHA выходов; повтор сверяет уже зарегистрированный артефакт либо sealed package до продолжения. После backup/restore все ссылки разрешаются внутри нового корня проекта, оригинальный операторский каталог не нужен.

Добавлены поведенческие проверки настоящего CLI с сетевым tripwire:

- Три наблюдения, 25 известных URL, точные маршруты и невыдуманные цены; обе версии модели/пакета в одном проекте и неизменные байты старого пакета.
- Backup/restore в новый корень, удалённые из пути исходные каталоги, повтор модели и сборки обеих версий без сети и без новых артефактов.
- Потеря подтверждения уже опубликованной модели и release artifact; новый CLI процесс сверяет и завершает прежнюю запись с теми же IDs и SHA.
- Запрещённая наблюдавшаяся страница блокирует сборку всего выбранного множества; изменение только durable selection metadata не принимается как повтор.
- Persisted reporter: оба формата, все исходные URL, PARTIAL/NOT_READY/access gate и отказ при ложном подмножестве ALL_OBSERVED в записи.
