## Конкретные команды и требуемые свидетельства

Ниже **следующие действия**, не выполненные этим audit команды. Значения путей/SHA берутся из принятых artifacts; secrets остаются в private files.

```text
npm run check
npm test
npm run test:e2e
node packages/cli/index.ts doctor --json
node packages/cli/index.ts status --project teplypol-market --json
node packages/cli/index.ts report --project teplypol-market --format html
```

Для полного local run задать реальные `UPGRADE_PHP_BIN`/`UPGRADE_PHP_EXT_DIR`, Chromium и сохранить FAIL/SKIP наряду с PASS. `npm run test:agents` **не повторять без причины**: AT22 уже имеет реальные task IDs/events/overlap/SHA/acceptance; новый прогон нужен лишь для изменившегося adapter/environment или нового согласованного acceptance сценария.

```text
node packages/cli/index.ts target validate|dry-run|reconcile|apply --environment demo --target-profile PROFILE --profile-sha256 SHA --package PACKAGE --manifest-sha256 SHA --journal-dir PRIVATE_JOURNAL
python3 scripts/verify-pilot-http.py --intent ACCEPTED_INTENT --origin HTTPS_ORIGIN --username USER --password-file PRIVATE_FILE --output NEW_RECEIPT
python3 scripts/verify-demo-http.py --base-url HTTPS_ORIGIN --trusted-host HOST --auth-password-file PRIVATE_FILE --snapshot-id SHA --product-route EXACT_ROUTE --output NEW_PRIVATE_RECEIPT
python3 scripts/recovery-target.py --help
```

Первая строка обозначает выбор одного поддерживаемого action, не буквальный аргумент с `|`. После UNKNOWN первым идёт reconcile; следующий apply использует те же authoritative pins и retained journal. HTTP/demo probes дополнить native readback `scripts/verify-pilot-bitrix.php`, before/after counts и browser evidence. Recovery сначала печатает план с обязательными receipt/compose/baseline/guard pins; только принятый новый план исполняется через `--execute --accept-plan-sha256`, в новом destination. Успешный recovery receipt должен быть связан с точным backup временным срезом.

Для CLI→report acceptance нужен отдельный поведенческий test: сохранённый настоящий receipt принят→показан с правильной target coverage; чужой project/manifest/scope, corrupted body, PENDING/UNKNOWN и старый code/input отвергнуты или STALE; один FAIL не становится READY; перезапуск продолжает ту же принятую версию. Не заменять этот тест прямым присваиванием readiness.
