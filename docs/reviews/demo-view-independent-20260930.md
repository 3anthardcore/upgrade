## Проверенные границы представления

- Все динамические source-тексты, подписи, hidden values, ссылки и alt проходят HTML-экранирование. Результаты поиска/корзины разрешают только ограниченные относительные request targets; точная повторная query-строка сохраняется. Media допускаются только по собственной форме `/upload/upgrade/PROJECT/SHA.ext`; проверка bytes/project binding остаётся обязанностью принятого snapshot adapter.
- Каждая отдельная POST-форма направлена только на `/__upgrade/action`, имеет CSRF, ожидаемый snapshot и свой случайный idempotency key. Обновление, удаление и checkout не делят один intent. View не читает запросы и не записывает сессии; повтор неизвестной записи разрешает DemoEngine.
- Показаны только переданные наблюдаемые варианты с исходными ID, без создания комбинаций. Quantity min/step/max берутся из сохранённых условий; неизвестные правила явно обозначены. Технические пределы демо не названы фактами источника. Окончательная проверка количества остаётся серверной.
- Money форматируется из decimal-строки без float. OLD/FROM/RANGE/UNKNOWN различаются; диапазон сохраняет обе границы. Неизвестный итог отображается «Требует уточнения», не нулём. Наличие дополнительного условия явно предупреждает о неопределённости; source body хранится отдельной factual-областью.
- Lead/checkout содержат только фиксированную synthetic identity, ограниченный выбор сценария и обязательное подтверждение. Нет настоящего имени, телефона, email, произвольного сообщения или видимости реальной оплаты. Receipt требует подтверждённого локального synthetic record и трёх false-флагов; отсутствующий или иной record не получает успешный экран.
- Header/footer сохраняют package-маркеры brand/navigation и фактические content-классы. Не добавлены выдуманные отзывы, наличие, сроки доставки или сертификаты. Заголовок собственной product-секции не дублирует H1, который должен поставить router/template.
