## Исполняемый интерфейс

`Upgrade\Core\DemoView::render(array $view): string` возвращает HTML без заголовков, сетевых запросов, CMS bootstrap и записи состояния. Согласованы поля с автором DemoWeb:

- `kind=search|product|cart|lead|receipt|error`; common `csrf`, `snapshot_id`, `items`;
- search: `search`, `query={q,category,sort,page,attributes:{a0:value}}`, `filters=[{key,name,label,values}]`, `categories=[{id,label}]`, `facets_limited`;
- product: `item`, его реальные `variants`, nullable price/unit/quantity;
- cart: фактический результат движка; receipt: `record` непосредственно, без восстановления из URL;
- POST: `action`, `csrf`, `expected_snapshot_id`, новый криптографический `idempotency_key` для каждой отдельной формы, только разрешённые action-поля;
- synthetic/consent передаются строкой `1`, identity=`demo-customer`, delivery=`demo-pickup`, payment=`demo-none`.

Формы работают без JavaScript: GET поиск/наблюдаемые фильтры/сортировка/пагинация; POST добавление, изменение количества, удаление, тестовое обращение и оформление. Наблюдаемые варианты представлены native details с отдельными формами и ID. Не создаётся декартово произведение вариантов. Никаких полей настоящего имени, телефона, email или свободного обращения.

Money форматируется из точной decimal-строки без float; UNKNOWN/null не превращается в ноль. OLD/FROM/RANGE сохраняют различия; диапазон показывает обе наблюдаемые границы. Неоднозначные условия имеют пользовательское пояснение, внутренние коды extractor не выводятся. Неизвестные min/step не объявляются фактами источника: поле показывает технический допустимый диапазон демо с явной подписью. Существующая native quantity-policy проверяется движком. В receipt успех показывается только при подтверждённом synthetic record с тремя false-флагами native order/send/payment.

Все source-тексты и значения атрибутов экранируются. Ссылки результатов остаются точными относительными source request targets; внешние/активные схемы отвергаются. Изображение разрешается только по собственной hash-addressed форме `/upload/upgrade/PROJECT/SHA.ext`; verified bytes/binding обязан подтвердить root snapshot adapter. При отсутствии картинки нет внешнего fallback или выдуманной иллюстрации.

## Дизайн и совместимость

Шаблон использует светлый фон, спокойный зелёный акцент, отдельную строку приватного демо, крупный поиск, компактную корзину и native details-меню. Карточки имеют реальные фото, если они присутствуют в принятом снимке; отсутствующее изображение явно обозначается. Product-композиция разделяет изображение и действия; cart отделяет позиции от суммы/синтетического действия; empty/error/receipt имеют самостоятельные понятные состояния.

Сохранены package-маркеры `upgrade:brand-name` и `upgrade:primary-navigation`, а также классы прежних factual blocks/cards/tables. CSS нового интерфейса добавлен как отдельный слой к совместимым базовым правилам. Свёрнутый текст длинного заголовка карточки остаётся полным в DOM и на странице товара. Source/body-факты не переписываются шаблоном. Header/footer не добавляют рекламных фактов о доставке, наличии, рейтингах и сертификатах.

В template есть skip-link, явные labels, focus-visible, native details/checkbox/select/number, область таблицы с клавиатурной прокруткой и reduced-motion. Целевые ширины360/390/768/1024/1440. Полноценная проверка assistive technologies и native Bitrix остаётся отдельной.

## Фактический integration finding: native POST и Origin

Первый browser-run не прошёл и **не был обозначен PASS**. Frozen DemoWeb SHA `a43fbb86ab44917a19bdc2668995f472bd79a35b6dcd9474f6ac7624ad8984ee` возвращал `Referrer-Policy: no-referrer`. В настоящем Chromium, JavaScript disabled, отправка собственной формы на тот же loopback origin давала:

```json
{"method":"POST","origin":"null","content_type":"application/x-www-form-urlencoded"}
```

POST `/__upgrade/action` был отвергнут403 строгим Origin guard; браузер оставался на action, показывая «Форма недействительна. Откройте страницу заново». Это не ошибка csrf/form-полей. Заголовки для получения PASS не подменялись. Root и автор DemoWeb получили точный witness; root назначил исправление политики ответа/Nginx на same-origin с сохранением строгой проверки Origin. Временные неполные снимки: `C:/Users/root/AppData/Local/Temp/upgrade-demo-view-RiFeMb/screenshots` (первые20 render screenshots; не полный успешный сценарий).

Воспроизведение:

```powershell
$env:UPGRADE_PHP_BIN=(Resolve-Path var/tools/php-8.3.35/php.exe).Path
$env:UPGRADE_VIEW_KEEP_EVIDENCE='1'
node --test --test-name-pattern='real PHP \+' tests/integration/demo-view.test.ts
```

Также устранена ошибка самого тестового readiness-probe: большой PHP response оставлялся непрочитанным, что вызывало assertion в undici. Probe теперь ограничен timeout и полностью читает body; код production для этого не менялся.
