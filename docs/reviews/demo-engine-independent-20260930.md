Независимо перечитан production-класс, полный набор тестов, авторское описание границ и совместимый commerce-контракт. Повторно выполнен настоящий PHP8.3.35 с mbstring; тесты запускали отдельные процессы и временные каталоги состояния.

- Деньги/количества рассчитываются целыми числами. Проверены ограничения и соответствие decimal/minor, half-up на строку, сложение дробных количеств, min/step/max. Статически проверена верхняя граница: `100000000 minor × 10000000000 scaled quantity = 10^18`, ниже 64-bit signed integer; сумма максимум100 строк также не переполняет целое. Поддержка PHP64-bit проверяется конструктором.
- Неизвестные, условные, неоднозначные, старые и диапазонные цены не дают итога. Известные валюты остаются раздельно; unknown synthetic checkout сохраняет `total=null`, `REQUIRES_CONFIRMATION` и blockers. `native_order_created`, `message_sent`, `payment_attempted` остаются false. Произвольные контакты/цены/поля запроса отвергаются.
- Варианты выбираются только из явных ID снимка. Отсутствующие позиции, исчезнувший вариант/невалидное количество и пустая корзина не допускают синтетическое оформление.
- CSRF сравнивается constant-time; запись состояния привязана к project и hash сессии. Чужие токены, скопированный файл другой сессии и traversal session ID отвергаются.
- Новый intent требует текущий `expected_snapshot_id`; изменившийся снимок блокирует новую запись. Повтор уже зафиксированного intent возвращает прежний результат с прежним pin, а не выполняет повторный расчёт. Изменение payload с тем же ключом даёт конфликт.
- В тестах реальные процессы завершались до и после atomic rename. Неизвестный результат согласуется по сохранённому receipt; повтор не дублирует запись и очистку корзины. Отдельно проверен unknown-price checkout после потери ответа.
- Двенадцать конкурирующих PHP writers, занятый flock с ограниченным ожиданием и повреждённое состояние проходят поведенческие проверки без lost update, reset или захвата чужого lock.

## Сохраняемые границы интеграции

1. Конструктор проверяет формат `snapshot_id` и project, но **не вычисляет pin из items**. Это явно заданная граница доверенного адаптера: перед созданием движка требуется прочитать hash-verified immutable artifact и связать его точные bytes/проекцию с pin. Подмена items под прежним pin не предотвращается одним этим классом; нельзя передавать snapshot клиента или непроверенный JSON.
2. `cart()` показывает текущую версию фактов; idempotent replay возвращает исторический receipt. HTTP/UI обязан учитывать возвращённый `snapshot_id`/revision и `replayed`, а не выдавать исторический ответ за новую текущую корзину. Оптимистического guard по revision корзины API не предоставляет: изменения одной сессии сериализуются по lock в порядке поступления. Это не механизм проверки, что пользователь подтвердил ровно увиденную ранее редакцию корзины.
3. HTTP-origin, метод POST, лимит body, random opaque cookie, Secure/HttpOnly/SameSite, no-store/noindex, BasicAuth, экранирование source-текста/URL и отсутствие токенов в логах проверяются на отдельном runtime-этапе. JSON движка не является безопасным HTML. Доступ к файлам состояния требует выделенного приватного владельца/каталога.
4. Доказана авария процесса на локальной файловой системе. Directory fsync, потеря питания, NFS/multi-host locks не проверены; общая квота/retention множества сессий остаются обязанностью адаптера. Orphan pending-файл не считается committed.
5. Поддерживаемые валюты/точности, предел количества10000 и лимит цены1000000 — ограничения движка, не добавленные факты источника. Их нельзя выдавать за правила магазина.
