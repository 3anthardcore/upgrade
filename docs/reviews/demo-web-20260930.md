## API and trust boundary

```php
Upgrade\Core\DemoWeb::handle(DemoEngine $engine, array $snapshot, array $request): array
```

Return is `{status:int, headers:array<string,string>, view:array|null}`. The class neither writes PHP headers/output nor starts a PHP built-in session. Persistent effects occur only through the supplied real DemoEngine, in its private local state directory. The caller must bind snapshot bytes to the trusted SHA before constructing the engine and passing the same snapshot to this method. Current engine search/cart responses are checked against that snapshot ID; this is a consistency check, not a substitute for artifact hashing.

Request metadata: `method`, exact `request_target`, trusted `host`, trusted boolean `https`, raw nullable `origin`, nullable opaque `cookie`, raw `body` string. POST additionally requires `content_type`: `application/x-www-form-urlencoded`, optionally `charset=UTF-8` (case-insensitive media type/charset). Ordinary source pages may supply trusted `item_id` from exact source route matching. No client Host/TLS forwarding is trusted implicitly: root's server adapter must supply pinned metadata. Cookie input is one extracted `upgrade_demo_session` value, not an entire Cookie header. Root must reject duplicate cookie names; its invalid-cookie sentinel is rejected for POST and rotated for GET.

Boundaries: request target/body each at most8192 bytes; at most32 scalar pairs; decoded values at most2000 bytes with valid UTF-8 and no control characters. Parser requires `key=value`, valid percent escapes, strict names, and rejects bracket arrays, duplicate decoded keys, trailing empty pairs and unknown route/action-specific keys. It does not use PHP `parse_str`, which can silently collapse duplicates. Search additionally limits q to200 UTF-8 characters/1000 bytes and category to240 bytes. Own routes are matched literally; source query strings are not reserialized.

All responses set `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`. Source text in successful view data remains inert unescaped data for DemoView to escape. Errors use a fixed code/message allowlist; arbitrary exception text, filesystem paths and source HTML never become an error view. Error statuses distinguish400,403,404,405,409,413,415,422,500,503. Unsupported methods include an explicit Allow header. HEAD has a null view and never creates a new session.

## Routes, forms and facets

| Route | Behavior |
|---|---|
| GET/HEAD `/__upgrade/search` | Actual engine search; session-free. Query q/category/sort/page and explicit a0..a19 filters. |
| GET/HEAD `/__upgrade/cart` | Current engine cart; optional `operation=SHA256` reads the same session's saved operation. |
| GET/HEAD `/__upgrade/lead` | Synthetic lead form, optional known `item_id`. |
| GET/HEAD `/__upgrade/receipt` | Required `operation=SHA256`; only a saved operation with a synthetic record, in the same existing session. Unknown, cross-session or cart-only operation returns404. |
| POST `/__upgrade/action` | Exact Origin + existing cookie + CSRF + snapshot pin + idempotency key; strict action-specific scalar fields. |
| Ordinary source GET/HEAD | Product view only for trusted `item_id` whose observed snapshot item has `is_product=true`. Other pages return null view. Source routes remain exact. |

POST common fields: `action`, `csrf`, `expected_snapshot_id`, `idempotency_key`. Action-specific fields match DemoEngine: cart.add item_id/optional variant_id/quantity; cart.update line_id/quantity; cart.remove line_id; demo.lead synthetic/identity/consent/topic/optional item_id; demo.checkout synthetic/identity/consent/delivery/payment. Empty optional variant_id normalizes to absent. Synthetic/consent must be exactly string `1`, converted to boolean true only after validation; identity must be exactly `demo-customer`. Unknown fields, user email/phone/name/free-text/price/return URL are rejected. Topic, delivery, payment, selection and quantity rules remain enforced by the engine.

Search sorts are relevance/title_asc/title_desc/price_asc/price_desc; page1..10000,20 results/page. Filters are deterministic lexical observed attribute names, first20, assigned a0..a19; each field selects one exact observed value, AND between attributes. Each facet displays first200 lexical values. Categories display first200 lexical observed category IDs. When an ID refers to `snapshot.items[id]`, the category label is its exact observed title; otherwise the ID is the explicit fallback. No human category title is guessed. Caps affect controls only: snapshot items and search denominator are retained, and `facets_limited=true` declares the presentation limit.

## Sessions, CSRF and exact replay

Only the server generates a new cookie:32 cryptographically random bytes encoded as64 lowercase hex. Cookie is `upgrade_demo_session`, Path=/, HttpOnly, SameSite=Strict; Secure is appended only under caller-verified HTTPS. Unknown supplied cookie is never used as a new chosen session ID. Product/cart/lead GET creates a fresh session when necessary; search/non-product/HEAD creates none. POST never creates a missing session or rotates it to make the submitted form succeed.

This depends on owner-implemented `DemoEngine::resumeSession($session): ?array` (existing-only csrf/cart) and `DemoEngine::receipt($session,$operationId): ?array` (existing-only saved response). Unknown session lookup creates no JSON or lock. Operation ID is **the engine's SHA256 of the idempotency key**, not the raw key and not record_id. Saved operation response is immutable; receipt GET does not execute mutate or recompute old totals.

POST Origin must exactly equal verified scheme + `://` + trusted host, including its configured port. CSRF is validated by actual engine state. New mutations require the supplied expected snapshot to match the current engine. Exact existing idempotency replay deliberately remains possible across snapshot changes: the engine verifies the original intent before its new-operation snapshot guard. A changed payload with the same key is409.

Successful cart actions return303 to `/__upgrade/cart?operation=SHA`; synthetic lead/checkout return303 to `/__upgrade/receipt?operation=SHA`. Locations consist only of fixed own path plus validated engine operation hash. Lost response after a real PHP commit was tested with process exit82 before output: a new PHP process handling the identical POST returns the same receipt path; revision, operation count and record count stay1. This proves local process/response recovery, not power-loss durability or native HTTP behavior.
