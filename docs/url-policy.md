# Политика URL

`raw_url` сохраняет наблюдаемую форму; `request_target` — кодированный путь и точную query-строку. `crawl_key = origin + request_target`. Не выполняются lower-case пути, сортировка параметров, decode `%2F`, слияние по canonical или SKU. Фрагмент не отправляется HTTP-серверу; hash SPA пока отмечается ограничением.

Путь назначения не связан с CODE/ID элемента Битрикс. Lookup использует индексируемый hash request target с проверкой строки. В демо меняется origin; возврат исходного полного URL требует отдельного переключения домена. Одинаковые пути разных origins не объединяются — текущий экспортёр требует отдельного target для каждого origin.

Редиректы сохраняют наблюдаемый статус и направление внутри разрешённого origin. Ошибки/внешние переходы/циклы учитываются в source registry и не становятся успешными маршрутами. Служебные пути и физические коллизии блокируют пакет/импорт. Нет catch-all redirect на главную.

Query-политика v0.1 — точные наблюдаемые состояния. Бесконечный фильтр/календарь не генерируется автоматически. Функциональная модель произвольных query, hash-роутов, поиска, фильтров требует отдельного адаптера; статический маршрут сам по себе не реализует функцию.
