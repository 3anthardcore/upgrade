# Протокол команды

1. Оператор создаёт проект/run и immutable input artifacts.
2. `task create` сохраняет роль, входы, цель, зависимости, непересекающиеся allowed_paths, инструменты, acceptance checks и конечный бюджет.
3. Диспетчер получает владение запуском. Claim резервирует бюджет транзакционно, увеличивает attempt/fencing, фиксирует input hash и абсолютный deadline.
4. Worker получает только разрешённые данные. `heartbeat` не продлевает абсолютный deadline; источник не меняет роль или полномочия.
5. `artifact add` сохраняет новую immutable версию. `task submit` требует актуальный worker/lease, схему результата и входные хеши; задача переходит VALIDATING.
6. Отдельный проверяющий запускает acceptance checks и `task review`. Автор не может принять свой результат; текст сообщения агента не является доказательством.
7. Повтор/смена владения не сбрасывает затраты. Неизвестный исход учитывается в unknown и требует сверки. Удаление данных из нового пакета не означает разрешение на удаление назначения.

`agents/*.md` загружаются реальным CodexAdapter и связываются с prompt SHA. CLI adapter имеет probe/start/poll/cancel/collectResult. Отдельный дочерний процесс сохраняет состояние; после падения диспетчера старый worker не получает новый lease автоматически. Документация и AT-22: [codex-adapter.md](codex-adapter.md).

Границы: текущий автоматический профиль запрещает shell/browser/MCP и делегирование; код пишется интерактивными агентами в раздельных областях. Три worker максимум. Доверенный оператор может вызвать API вручную; разграничение нескольких пользователей и независимая роль reviewer на уровне ОС пока не реализованы.
