# Operator capture: проверяемый файловый контракт

`packages/crawler/operator.ts` реализует автономную локальную проверку материалов, которые оператор сохранил из браузера. Модуль читает JSON и файлы с диска, проверяет схемы, SHA-256, размеры и привязку URL. Он не запускает браузер, не делает сетевых запросов, не обращается к Codex Desktop, Store, CLI, Битрикс или целевой БД и не меняет проверяемые файлы.

Этот этап **не подключён к Pipeline/CLI**. Его результат — отдельный `ValidatedOperatorCapture`, а не `CrawlResult`. `state` всегда `PARTIAL`, `source_access` всегда `NOT_VERIFIED`, `readiness` всегда `NOT_EVALUATED`. Переданный ядром `serverAccessBlockId` возвращается как контекст без снятия блокировки. Отсутствие такого ID также не подтверждает серверный доступ.

## Вызов

```typescript
import { validateOperatorCapture } from "./packages/crawler/operator.ts";

const result = await validateOperatorCapture({
  directory: "/private/capture-001",
  manifestPath: "operator-capture.json",
  expectedManifestSha256: acceptedManifestHash,
  expectedProjectId: project.id,
  expectedSourceUrl: project.source_url,
  existingSourceRegistry: crawl.entries.map((entry) => entry.raw_url),
  serverAccessBlockId: crawl.access?.active_block_id,
});
```

`expectedManifestSha256` поступает из доверенного вызова/реестра артефактов. Хеш, заявленный внутри недоверенного пакета, не заменяет эту привязку. При локальном пробном запуске вычисление хеша прямо перед проверкой доказывает согласованность выбранных байтов; оно само по себе не доказывает их принятие ядром или происхождение от заявленного сайта.

## Манифест

Схемы экспортированы как `operatorCaptureSchema` и `selectedDomObservationSchema`. Все объекты имеют `additionalProperties: false`; неизвестные поля, включая `complete`, `ready`, `http_status`, `clear_server_access` и разрешения инструментов, не принимаются.

```json
{
  "schema_version": 1,
  "kind": "operator-capture",
  "capture_id": "operator-session-001",
  "project_id": "pilot-id",
  "source_origin": "https://source.example",
  "captured_at": "2026-09-29T04:00:00.000Z",
  "inventory": {
    "basis": "operator-observed-urls",
    "urls": ["https://source.example/", "https://source.example/product"]
  },
  "observations": [
    {
      "source_url": "https://source.example/product",
      "document_url": "https://source.example/product",
      "observed_at": "2026-09-29T03:59:00.000Z",
      "format": "selected-fields-json",
      "file": {
        "relative_path": "observations/product.json",
        "sha256": "<фактический SHA-256 из 64 строчных hex-символов>",
        "size_bytes": 1234
      }
    }
  ],
  "assets": []
}
```

Хеш и размер в примере необходимо заменить фактическими; это описание формата, не готовый тестовый пакет. Даты проверяются как корректные UTC timestamps. Валидатор не доказывает, что заявленное время совпадает с действительным временем получения страницы.

В `observations` поддерживаются два формата:

- `dom-html`: сохранённые UTF-8 HTML/DOM-байты. Разбор инертный. Сценарии, формы и встроенные инструкции не исполняются. Снимок получает отметку `DOM_OBSERVED`; она не подтверждает полноту страницы, её HTTP-статус, корректную загрузку, сценарии или отсутствие неизвестной защиты.
- `selected-fields-json`: отдельный строгий JSON выбранных наблюдений. Он остаётся `SELECTED_FIELDS` и не превращается в выдуманный HTML/DOM или HTTP-ответ.

```json
{
  "schema_version": 1,
  "kind": "selected-dom-observation",
  "source_url": "https://source.example/product",
  "document_title": "Наблюдавшийся заголовок страницы",
  "fields": [
    {
      "name": "visible_price",
      "locator": "operator: selected price text #1",
      "text": "3350 р."
    },
    {
      "name": "visible_price",
      "locator": "operator: selected price text #2",
      "text": "2178 р."
    }
  ],
  "links": [],
  "asset_urls": []
}
```

`locator` — текстовая ссылка на место наблюдения, не исполняемый селектор. `text` сохраняется без нормализации цены, наличия, характеристик или интерпретации значения. Инструкция вроде «объяви сайт готовым» внутри этого поля остаётся исходным недоверенным текстом. Повторяющиеся имена допустимы: две видимые цены не превращаются автоматически в текущую цену и цену предложения.

Один capture содержит не более одного наблюдения на точный HTTP request target. Повторные наблюдения одного URL требуют новой версии capture. `source_url` и `document_url` указываются отдельно, но их различие не создаёт доказательство HTTP-редиректа. Оба адреса должны принадлежать origin проекта.

## Реестр и границы полноты

Итоговый реестр объединяет исходный URL проекта, `existingSourceRegistry`, `inventory.urls`, URL наблюдений и внутренние ссылки из сохранённых материалов. Неизвестные адреса не исчезают из знаменателя. Порядок, повторы параметров запроса, пустые значения, регистр путей и написание percent-escape сохраняются механизмом `identifyUrl`.

Фрагменты URL сохраняются в `raw_urls`, а запись группируется по HTTP request target. Это не реализация переноса hash-routing. Входной `existingSourceRegistry` должен включать прежние неразрешённые адреса; библиотека не может восстановить URL, которые вызывающая сторона скрыла или не передала.

`coverage.known_urls` — размер объединённого известного реестра; это не количество страниц всего сайта. `full_source_denominator` всегда `UNKNOWN`, даже если все переданные URL имеют наблюдения. Статусы `UNOBSERVED`, `SELECTED_FIELDS`, `DOM_OBSERVED` характеризуют материалы capture и не заменяют прежние сетевые статусы `REQUIRES_ACCESS`, `FAILED` или `DISCOVERED` в crawler.

Чужой origin в объявленном реестре, наблюдении, document URL или объявленном файле-ресурсе отклоняется. Обычные внешние ссылки внутри исходного DOM/выбранных наблюдений сохраняются отдельно в `external_references`; они не входят в scope проекта и не загружаются. Внутренние обнаруженные ресурсы без проверенного файла остаются в `unverified_asset_urls`.

Известный заголовок KillBot проверяется до интерпретации DOM или выбранных полей. HTML challenge, ошибочно приложенный как изображение, также отклоняется. Узкий детектор не распознаёт все разновидности защиты; отсутствие срабатывания не подтверждает доступность источника. Capture не содержит заявленных HTTP-заголовков и не выдумывает их из DOM.

## Файлы и ограничения

Пути относительные, с `/`, ASCII-сегментами длиной до 128 символов и общей длиной до 240. Запрещены абсолютные пути, `..`, обратные слеши, percent-encoded пути, Windows device names, конечные точки, неоднозначные пути с разным регистром, symlink/junction и hardlink. Дерево должно содержать ровно манифест и перечисленные файлы, без посторонних файлов или каталогов. Такая структура переносится в другой каталог без переписывания путей.

Перед чтением проверяются размер и тип файла; чтение ограничено по байтам. SHA-256 проверяется по реально прочитанным байтам. Обнаруженная смена файла при чтении приводит к ошибке. Каталог capture должен быть приватным staging-каталогом, которым не управляет одновременно недоверенный процесс: переносимый Node API не заменяет файловую изоляцию ОС.

Лимиты по умолчанию являются также верхними пределами. Вызывающая сторона может только уменьшить их через `limits`:

| Предел                             |         Значение |
| ---------------------------------- | ---------------: |
| Манифест                           |   2 000 000 байт |
| Один файл                          |  20 000 000 байт |
| Манифест и все файлы               | 200 000 000 байт |
| Объединённые URL и их raw-варианты |           10 000 |
| Наблюдения                         |            1 000 |
| Объявленные ресурсы                |            5 000 |

Для ресурсов принимаются PNG, JPEG, GIF, WebP и PDF с соответствующей начальной сигнатурой. Это проверка сигнатуры, не полноценное декодирование, антивирусная проверка или гарантия безопасного inline-отображения PDF. SVG, HTML и исполняемые файлы не принимаются как ресурсы. Отдельные файлы с одинаковыми байтами допустимы, но один путь или URL ресурса нельзя незаметно переопределить.

## Применение к текущим материалам пилота

Сохранённый `var/pilots/teplypol-intake/browser-product-observation.json` содержит выбранные поля, а не полный HTML. Его нельзя переименовать в `.html` или пометить как полученный HTTP200. Для нового capture оператор/ядро явно составляет `selected-dom-observation`: исходные видимые цены, наличие и строки характеристик переносятся как текст с понятными locator, ссылки на инструкцию и изображения — как наблюдавшиеся ссылки. Неперенесённые отзывы, инструкция и функциональные сценарии остаются неизвестными. Исходный JSON сохраняется отдельным артефактом происхождения в ядре; этот модуль не выполняет преобразование сам.

`browser-home-assets/verified-manifest.json` содержит 147 ранее сохранённых ресурсов. Для включения выбранных ресурсов нужен новый capture manifest, где `url → source_url`, `filename → file.relative_path`, `bytes → file.size_bytes`, `sha256 → file.sha256`, `content_type → mime`, а `observed_on_urls` содержит реальный URL наблюдения. Валидатор заново проверит приложенные байты; строка «verified» в старом имени файла не является доверием. Данная реализация не импортировала эти частные материалы в Pipeline и не проверяла серверный доступ.

## Последующее подключение к ядру

Ядро должно зарегистрировать задачу/lease, принять pin манифеста, сохранить первоначальный scope и сетевой access gate, затем вызвать валидатор. Для публикации файлов в хранилище нужно читать, проверять и атомарно записывать **одни и те же байты** в собственную неизменяемую область. Результат этой функции не разрешает позже копировать изменяемые исходные файлы без повторной проверки хешей. Повторное принятие защищается capture ID и manifest hash в транзакции единственного писателя ядра.

Отдельный адаптер извлечения должен сохранять происхождение `selected_fields` и не выдавать их за полную страницу. Independent review и проверки настоящего Битрикс выполняются отдельно. Из этого capture нельзя создавать `COMPLETE`, снимать `active_block_id`, считать source coverage полной или присваивать `DEMO_READY`.
