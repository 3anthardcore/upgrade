# Независимое ревью Bitrix и изоляции

Дата: 2026-09-29. Задача: `review-bitrix-security`. Проверяющий не изменял `bitrix/`, `infra/` или `packages/bitrix-adapter/`; исправления выполнял отдельный исполнитель. Область собственной записи: этот отчёт и `tests/unit/bitrix-review.test.ts`.

## Найденные и исправленные дефекты

**P1 — возможность добавить непринятый исполняемый файл в принятый пакет.** Валидаторы первоначально проверяли SHA-256 перечисленных файлов, но не запрещали отсутствующие в manifest файлы. `deploy-code.sh` копировал дерево кода рекурсивно. Добавленный `code/module/upgrade.core/.settings.php` не меняет хеш принятого manifest и перечисленных файлов, но мог попасть в исполняемую область назначения. Исполнитель добавил проверку точного состава дерева и отказ от symlink в TypeScript и PHP. Независимые тесты добавляют такой файл после сборки и подтверждают отказ обоих настоящих валидаторов. Статус исправления: **PASS на локальной проверке**. Сетевое развёртывание не выполнялось.

**P1 — bootstrap Битрикс до обязательной проверки PHP-контура.** Первоначально importer и migration проверяли только переменные `UPGRADE_DEMO`/project, а HTTP-router подключал `prolog_before.php` раньше проверки demo. Запуск обычным PHP с установленными env-флагами мог выполнить source init hooks до защитной конфигурации. Теперь до bootstrap проверяются sentinel доверенного `auto_prepend_file`, фиксированный путь prepend и обязательные отключённые функции. Независимый тест создаёт синтетический prolog, который оставил бы файл-маркер при исполнении, и запускает реальные importer, migration и router в обычном PHP без prepend. Маркер не появляется для всех трёх точек входа. Статус исправления: **PASS для порядка исполнения PHP**, **NOT_RUN для настоящего FPM/Bitrix и сетевой изоляции**.

Рекурсивное копирование кода после отдельной валидации дополнительно требует защиты от изменения пакета между этими действиями. Приёмка package inventory не заменяет проверку байтов в момент копирования и read-only-размещение принятого выпуска. Замечание передано исполнителю; в интеграционном запуске проверить итоговую реализацию deployment и хеши установленных файлов.

## Что подтверждено локально

Команда:

```powershell
$env:UPGRADE_PHP_BIN = (Resolve-Path var/tools/php-8.3.35/php.exe).Path
$env:UPGRADE_PHP_EXT_DIR = (Resolve-Path var/tools/php-8.3.35/ext).Path
node --disable-warning=ExperimentalWarning --test tests/unit/bitrix-review.test.ts
```

Фактический результат: **4 PASS, 0 FAIL, 0 SKIP**. PHP 8.3.35; полный Битрикс не подключался. При отсутствии явного `UPGRADE_PHP_BIN` три PHP-теста помечены SKIP, а не PASS.

Проверки:

1. TypeScript-валидатор отклоняет добавленный после принятия неперечисленный PHP-файл.
2. Настоящий PHP-валидатор отклоняет тот же пакет при неизменном принятом manifest SHA.
3. Все три точки входа прекращают работу до исполнения даже синтетического target prolog, если предоставлены только env-флаги.
4. Настоящий PHP-метод `Gateway::fields` вызван через Reflection без конструктора/БД: script/img/onerror исходного текста становятся экранированным текстом в создаваемом HTML. Здесь проверяется чистое преобразование блоков, а не имитация Bitrix API.

`npm run check` — **PASS** после добавления независимых тестов.

## Результаты чтения реализации

- Route lookup использует индексированный SHA-256 сырого request target и последующее точное сравнение. Query не сортируется, `%2F` не преобразуется в `/`. SQL-строки экранируются через SQL-helper, числовые поля приводятся к integer; запись SQL ограничена собственными `ug_*`-таблицами.
- `stable_key` включает project/type/source_id. Совпадающий SKU не становится основанием объединения. PHP повторно вычисляет ключи и связи. Связи source→Bitrix не зависят от NAME/CODE.
- Перед записью `planEntity` читает текущее назначение по XML_ID, обнаруживает дубликаты/сдвиг mapping и сравнивает управляемые поля. Отсутствие локального checkpoint не является основанием повторить Add без сверки. Ручная правка отличается от ранее импортированного хеша и вызывает конфликт.
- Apply проверяет fencing token под row lock до записи и commit; claim тоже использует row lock. Дополнительно действует flock одного host. Реальные свойства транзакций CIBlock, сбой/kill и lease-конкуренция требуют установки Битрикс — по чтению кода им PASS не присваивается.
- Импортёр не генерирует цену/наличие из пустых данных. Product остаётся явно обозначенным информационным снимком. Каталог, offers, коммерческие цены/остатки и рабочие покупки не реализованы этим профилем.
- Исходный HTML не используется для построения импортируемого DETAIL_TEXT: вывод составляется из экранированных типов блоков. Локальные media привязаны к SHA/MIME; формы и source scripts не переносятся. Доверенные последующие правки администратора имеют отдельную границу доверия.

## Открытые риски и обязательные границы интеграции

**P2 — происхождение backup receipt.** Текущий guard сверяет self-described project/status и контрольную сумму database dump. Этого недостаточно для доказательства, что backup относится к актуальному назначению/запуску, а не старому dump с заново оформленной квитанцией. Перед разрешением внешнего применения требуется связь с принятым артефактом ядра (ожидаемый SHA receipt), identity целевой БД и политика актуальности. Замечание передано исполнителю; это не факт утраты данных, поскольку target import не выполнялся.

**Изоляция сети/ОС — NOT_RUN.** Compose `internal: true`, отключённые mail/process функции, новый PHP image и prepend — полезные меры, но не фактическое доказательство недоступности внешних SMTP/webhook или сервисов host bridge. До первого PHP-кода настоящего клона требуется сетевой тест из той же сети, включая адрес host gateway, соседние проекты, DNS и пути возможного egress. Прямой admin доступ и секреты source-клона тоже требуют проверки отдельного назначения.

**Настоящий Битрикс — NOT_RUN.** Не проверены живые DB-транзакции, изменения в административной части, очистка search/cache, FPM/Nginx routing, файлы с encoded slash, два worker, срок lease и kill до/после commit. Не проверено восстановление полного сайта/БД и переключение домена. PHP lint и чистая функция renderer этого не доказывают.

**Контент и сценарии — частично реализованы.** Точный маршрут и текстовый блок не подтверждают перенос исходных ссылок, меню, разделов, canonical/hreflang, фильтра, поиска, формы или магазина. Соответствующие ограничения изложены в `docs/bitrix.md`; до проверки согласованного scope готовность DEMO_READY недопустима.

Следующий шаг: сохранить эти результаты в матрицу приёмки, завершить защиту копирования/backup-происхождения, затем выполнить интеграционный профиль на отдельной лицензированной установке с подтверждённой изоляцией. До этого внешнее применение и runtime-готовность не подтверждены.
