# Извлечение частичной модели из operator capture

`packages/extractor/operator.ts` преобразует принятые локальные байты operator capture в `OperatorContentModel`, совместимую с базовым `ContentModel`. Это отдельный путь обработки данных: функция не создаёт фиктивный `CrawlResult`, не присваивает `COMPLETE`, не снимает access gate, не запускает браузер и не обращается к сети, файловой системе, Store или Битрикс самостоятельно. Чтение конкретных байтов делегировано вызывающему ядру.

## API и граница доверия

```typescript
import { extractOperatorContent } from "./packages/extractor/operator.ts";

const model = await extractOperatorContent(validatedCapture, {
  projectId: project.project_id,
  sourceVersion: acceptedCaptureResultSha256,
  readFile: async (relativePath) => acceptedArtifactBytes(relativePath),
});
```

Аргумент `validatedCapture` — результат файлового валидатора из `packages/crawler/operator.ts`. Привязку результата к принятому capture и проекту, hash входного артефакта, lease, единственного писателя и журнал событий обеспечивает ядро. Экстрактор не подтверждает криптографически, что произвольный JS-объект ранее был принят Store.

`readFile(relativePath)` возвращает `Uint8Array`/`Buffer` либо Promise этих байтов. Вызывающая сторона предоставляет только принятые неизменяемые артефакты. Перед разбором экстрактор повторно проверяет принадлежность пути реестру файлов, SHA-256 и точный размер. Изменённые или отсутствующие обещанные байты прерывают извлечение; источнику не отправляется запрос для их восстановления. Кэш `observation.selected_fields` не используется вместо файловых байтов.

Опциональный `mediaPath(relativePath)` указывает абсолютный локальный путь, по которому вызывающая сторона уже материализовала эти же проверенные байты. Функция сама не записывает файл и не проверяет соответствие этого пути содержимому. Для долговечной модели рекомендуется не передавать `mediaPath`: абсолютные пути не попадут в артефакт и не помешают восстановлению на другом хосте.

Проверки статусов capture, ограничений, URL, путей, MIME и известных challenge повторяются как дополнительная защита. Они не заменяют проверку исходного манифеста валидатором. Модуль использует только общие библиотеки TypeScript/Node/Cheerio/Ajv; внутренний API Codex Desktop в контракт не входит.

## Возвращаемая модель

`OperatorContentModel` расширяет базовый `ContentModel` следующими полями:

- `source_capture`: manifest hash, capture ID, source version, неизменяемые `state: PARTIAL`, `source_access: NOT_VERIFIED`, `full_source_denominator: UNKNOWN`, прежний `server_access_block_id`, числа известных URL/наблюдений и список ресурсов без принятых байтов.
- `source_inventory`: копия полного исходного реестра capture, включая неразрешённые URL и точные варианты request target. Полнота не пересчитывается от одних созданных сущностей.
- `raw_selected_fields`: исходные `index`, `name`, `locator`, `text`, идентификатор сущности и evidence для каждого выбранного поля. Порядок, повторяющиеся имена, пробелы, NBSP, валютные обозначения и единицы измерения не нормализуются.
- `assets[].operator_file` и `operator_bytes: VERIFIED`: относительная ссылка на принятый файл, его размер и SHA-256, проверенные resolver-байты.

Идентификатор сущности зависит от точного URL, а не от названия товара, текущей цены или версии capture. Повторное извлечение одинакового входа детерминировано и не меняет входной объект. Это позволяет ядру организовать повторное принятие без создания дубликатов; самостоятельной транзакции импорта этот модуль не выполняет.

## Выбранные поля

`selected-fields-json` всегда создаёт `Page`. Название вроде «Купить товар», поле `type: Product`, наличие цены или слово «В наличии» не являются достаточным доказательством полноценной товарной модели.

Документный заголовок сохраняется как наблюдавшийся заголовок. Единственное поле с точным locator `h1` может задать наблюдавшийся H1 и имя. Все поля сохраняются дословно в `raw_selected_fields`, `facts[operator_field:N]` и табличных текстовых блоках. Такая таблица — представление выбранных данных, не восстановленный исходный DOM. Для выбранных полей `sanitized_html` остаётся пустым.

Каждый факт с наблюдавшимся текстом имеет `OBSERVED`, evidence URL, timestamp и SHA именно файла выбранных наблюдений. `OBSERVED` означает «этот текст присутствует в принятом наблюдении», а не независимое подтверждение его истинности. Исходные тексты не меняют инструкции, права, доступы или статус готовности.

Две строки `3350 р.` и `2178 р.` сохраняются как две строки. Экстрактор не выбирает действующую цену, не вычисляет скидку, не назначает валютный код, не объединяет предложения и не превращает «В наличии» в количество на складе. `prices` и `offers` в V1 остаются пустыми, стандартные `facts.price` и `facts.availability` — `UNKNOWN` с `value: null`. Неизвестные SKU, описание и имя также получают `UNKNOWN`, а не `ABSENT_IN_SOURCE`: неполный снимок не доказывает отсутствие информации на сайте.

## DOM и структурированные сведения

Для `dom-html` заново разбираются исходные UTF-8 HTML-байты. Известный challenge отклоняется до извлечения. JSON выбранных полей, переименованный в HTML, не принимается как DOM.

Извлекаются заголовки, абзацы, списки, таблицы, цитаты и ссылки на проверенные изображения/документы. `sanitized_html` сохраняет безопасное представление основного контента. Скрипты, обработчики, формы, фреймы, активная разметка, скрытые элементы и стили удаляются. Изображения не остаются удалёнными hotlink в HTML. Ссылки на файлы становятся текстом и отдельными блоками только при наличии принятых байтов. Внутренние ссылки переписываются в точный request target без перестановки параметров.

Сохранённый `facts[dom:visible_text]` содержит текст основного DOM после удаления активных/скрытых узлов. Он сохраняет неструктурированные текстовые цены и другие данные, которые не получили отдельного типизированного блока. Это DOM textContent, а не доказательство визуальной видимости при всех CSS, viewport или пользовательских состояниях. Типизированные блоки и санитарная HTML-проекция не подтверждают полноту страницы.

DOM-сущность получает `Product`, `Article` или `Service` только при одном однозначном кандидате schema.org: поддерживаемый `@context`, явный тип и `url`/`@id`, привязанный к текущему документу. Рекомендация другого товара на странице не меняет тип страницы. Несколько кандидатов оставляют `Page` и замечание о неоднозначности. Сложные контексты JSON-LD, `mainEntity` и произвольные CMS-правила требуют отдельного адаптера.

Исходные JSON-LD script-тексты сохраняются дословно в `facts[operator_jsonld:N]`; исходные большие числовые значения не превращаются в округлённые JS-числа модели. Явный строковый SKU сохраняет ведущие нули. Нормализация коммерческих предложений не выполняется даже при наличии JSON-LD Offer. Отдельное сопоставление торговли и независимая проверка остаются обязательными.

Форма, поиск и управление корзиной дают только `Feature.status: UNVERIFIED`, `target_implementation: null`, `test: null`. Ни одного действия с заказом, заявкой или оплатой экстрактор не выполняет.

## Ресурсы

Все заявленные файлы ресурсов заново проверяются по размеру, SHA-256 и допустимой начальной сигнатуре. Проверенные байты не означают декодирование изображения, безопасность PDF или лицензионную чистоту: эти проверки остаются отдельными.

Без `mediaPath` ресурс имеет `status: DISCOVERED`, SHA-256 и `operator_file`, но не `body_path`. При наличии доверенного локального пути используется совместимый с существующим builder статус `FETCHED`, который здесь означает готовность локальных байтов. Он не устанавливает HTTP200, доступность исходного сервера или полноту исследования. Ядро также может материализовать байты отдельно и адаптировать статус только в объекте, передаваемом builder, сохранив долговечную модель переносимой.

`asset_sha256` блока задаётся только после проверки байтов resolver. Отмеченные в наблюдении изображения и документы без принятого файла сохраняются как неразрешённые ресурсы; для них не создаются хеши, удалённые fallback или подставные изображения. Файлы, уже обещанные принятой версией capture, но исчезнувшие из resolver, являются ошибкой целостности, а не обычным пробелом исходного контента.

## Проверка

```text
npm run check
node --disable-warning=ExperimentalWarning --test tests/integration/operator-extraction.test.ts
```

17 поведенческих тестов используют реальные временные файлы и принятый файловым валидатором capture. Они проверяют точные поля/evidence, две цены, наличие, неизвестные значения, доменный scope, отсутствие исполнения исходного кода, санитарную обработку HTML, частичный статус, сохранённый access gate, media hashes, отсутствующие/изменённые файлы, невалидные пути и MIME, переименование выбранного JSON в DOM и детерминированный повтор.

В этом локальном запуске pin вычислялся по локальному файлу: это проверка консистентности сохранённых материалов, не самостоятельная приёмка Store или подтверждение его истории. К сайту и серверной БД запросы не выполнялись, live HTTP-доступ не проверялся. Запись модели в Store, CLI, маршруты, build и публикация относятся к отдельной интеграции ядра. Настоящий Битрикс и функциональные сценарии этим этапом не проверены.
