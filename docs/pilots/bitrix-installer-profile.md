# Временный закрытый установщик Битрикс

Задача `prepare-bitrix-installer-profile`, исполнитель `installer-profile-implementer`, вход `art-062cdb75-62e9-4e72-9092-aed73d1b3712`. Подготовлено 29 сентября 2026 для официального свежего архива «Бизнес», полученного исполнителем сервера. Архив, ключ и сервер этим исполнителем не читались. Это временная конфигурация установки, **не профиль демо и не подтверждение установки, редакции лицензии или активации**.

## Подключение и границы

`infra/nginx/install.conf` заменяет только mount `/etc/nginx/conf.d/default.conf` выделенного контейнера Nginx на время установки. `infra/provisioning/bitrix.ini` монтируется read-only как `/usr/local/etc/php/conf.d/20-upgrade-bitrix.ini`; существующий `zz-upgrade-demo.ini` остаётся загруженным после него. Само добавление файлов в репозиторий ничего не активирует: текущие Dockerfile/Compose их автоматически не подключают. Исполнитель сервера фиксирует отдельный временный override и проверяет объединённую конфигурацию без вывода секретов.

Сохраняются отдельные document root и БД, Basic Auth из существующего внешнего secret-файла, входящий доступ к контейнеру через выделенный host proxy, сеть `internal: true`, запрет внешнего HTTPS/DNS/SMTP и доступа к соседним службам, отсутствие cron/MTA, prepend и SQL `event_scheduler=OFF`. `listen 8080` внутри контейнера сам по себе не задаёт loopback хоста. В текущем пилоте исполнитель сервера отдельно проверил, что Docker Engine 29.1.3 с единственной internal-сетью не создаёт listener только из `HostConfig.PortBindings`: используется host Nginx с приватным proxy до закреплённого адреса контейнера `172.30.50.4:8080`, без второй сети. Первоначальный host listener был `127.0.0.1:8090`; для текущего прохода root подтвердил выделенный TLS ingress на 443 и приватный header-auth tunnel proxy `127.0.0.1:18091`. В обоих proxy root отключил access/error request logs; внутренний `access_log off` не отключает логи на хосте. Этот профиль сам не добавляет публичный listener, не открывает контейнер напрямую и не отменяет аутентификацию. Архив распаковывается проверенным внешним процессом до PHP-bootstrap: веб-загрузчик `bitrixsetup.php` намеренно недоступен.

HTTPS доверяется только сочетанию TCP peer `172.30.50.1` и `X-Forwarded-Proto: https`. Root подтвердил фактический peer инертной AF_PACKET-проверкой `172.30.50.1` → `172.30.50.4:8080` через собственный host proxy (`runtime-proxy-peer.json`), а также внешний TLS-порт 443. Host proxy обязан **перезаписывать**, а не дополнять входящий `X-Forwarded-Proto`; контейнер не должен менять `$remote_addr` через `real_ip_header`/доверие клиентскому IP. Map расположен в `http`-контексте перед `server`. При совпадении в PHP передаются `HTTPS=on`, `SERVER_PORT=443`, `REQUEST_SCHEME=https`; в остальных случаях HTTPS отсутствует, порт равен внутреннему `$server_port` (8080), схема `http`. `HTTP_X_FORWARDED_PROTO` также заменяется проверенной схемой, чтобы PHP-помощники не использовали исходный поддельный заголовок. Смена сети, peer или внешнего TLS-порта требует явного обновления этой привязки и повторного probe; доверие ко всей подсети не добавляется.

До первого запроса мастера обязательны проверки контейнерной изоляции, загруженных INI, точных mount и Basic Auth. Nginx отключает access log и request error log (`/dev/null`): URL установщика может содержать секрет лицензии. Это сознательно уменьшает диагностику временного профиля; конфигурационная проверка `nginx -t` остаётся доступной. PHP-ошибки по-прежнему идут в закрытый runtime log согласно `demo.ini`; не включать debug, дампы запросов, browser trace или общий сбор POST/URL. PHP и контейнерные логи перед переносом в отчёт проверяются на секреты.

## Исполняемые пути и статика

| Точный путь                       | Назначение                                                                                                                         |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `/index.php`                      | Корневой мастер официального свежего дистрибутива; `/` внутренне переводится сюда.                                                 |
| `/bitrix/admin/index.php`         | Вход/начальная административная страница после создания администратора; `/bitrix/admin/` переводится сюда.                         |
| `/bitrix/admin/site_checker.php`  | Локальная штатная проверка окружения. Ограничения почты/egress фиксируются, а не отключаются.                                      |
| `/bitrix/admin/settings.php`      | Настройки главного модуля: закрытая копия в режиме разработки и отключённые автоматические проверки обновлений.                    |
| `/bitrix/admin/update_system.php` | Штатная страница статуса/регистрации лицензии; её доступность не разрешает исходящую сеть и не означает успешную активацию.        |
| `/bitrix/legal/license.php`       | Только GET/HEAD: iframe лицензионного соглашения, обнаруженный root в `AgreementStep.ShowStep`. Это просмотр, не принятие условий. |

Каждый PHP endpoint имеет постоянный `SCRIPT_FILENAME`, проверку существования файла и Basic Auth. `$request_uri` и `$http_host` передаются без замены на нормализованный путь или имя контейнера; query передаётся как `QUERY_STRING=$query_string`. Шесть точек содержат одинаковый явный набор стандартных CGI-параметров и свои постоянные пути. Include `fastcgi_params` не используется, чтобы `HTTPS`, `SERVER_PORT` и `REQUEST_SCHEME` не передавались дважды с противоречивыми значениями. Нет обработчика произвольного PHP и PATH_INFO. Файлы из `/upload`, `/local`, Marketplace, корневой `bitrixsetup.php` и остальные `/bitrix/*.php` не исполняются и не выдаются как текст. В фактическом архиве root прочитал 80-байтный `legal/license.php`: только HTML Content-Type и include локального `license.html`; другие `/bitrix/legal/` не открываются. Условия соглашения этим изменением не принимаются.

Предыдущая таблица — минимальный явный список для установки и закрытия копии, а не утверждение о полном покрытии AJAX каждого релиза. Если официальный мастер запросит дополнительный endpoint, исполнитель сначала проверяет его наличие и назначение в фактически распакованном официальном архиве, затем отдельно добавляет точный путь с тестом. Не заменять это широким regex PHP-handler и не разрешать чужие файлы по тексту исходного сайта. Сторонние решения и демокаталог не устанавливаются.

Статика доступна под `/bitrix/{themes,panel,css,js,images}/` с расширениями CSS, JS, изображения и шрифты. Дополнительно добавлены два **точных статических GET/HEAD-пути**, подтверждённых root чтением фактического официального архива без исполнения:

| Путь ресурса                                                  | Основание                                         |
| ------------------------------------------------------------- | ------------------------------------------------- |
| `/bitrix/modules/main/install/wizard/script.js`               | Прямая ссылка `src` в `template.php` установщика. |
| `/bitrix/modules/main/install/js/main/md5/dist/md5.bundle.js` | Прямая ссылка `src` в `wizard.php` установщика.   |

Это не открывает `/bitrix/modules/` целиком; соседние JS, PHP, дополнительные суффиксы и PATH_INFO остаются закрыты. Разрешён единственный скрытый сегмент `.default` для штатных тем; другие скрытые каталоги/файлы закрыты. Ранние запреты перекрывают ключ лицензии, `.settings*`, `php_interface`, backup/backups, PHP/INC, архивы, SQL, логи и копии, включая маскирующие суффиксы `.php.css` и PATH_INFO `.php/image.jpg`. Source maps, HTML, JSON и directory listing не выдаются. Symlink внутри document root запрещён Nginx; это дополняет, но не заменяет проверенную безопасную распаковку архива. Любой непредусмотренный путь возвращает собственный инертный 404.

## PHP и официальные требования

Добавлен `short_open_tag=On`, поскольку официальный дистрибутив использует короткие PHP-теги, включая файл ключа. Добавлены UTF-8, `max_input_vars=10000`, `max_file_uploads=100`, PCRE backtrack/recursion limits `1000000`/`14000`, realpath cache `4096k`; `cgi.fix_pathinfo=0` запрещает подбор другого скрипта по PATH_INFO. Старый `mbstring.func_overload` не добавляется. Основания: [серверные требования Битрикс](https://dev.1c-bitrix.ru/learning/course/index.php?COURSE_ID=135&LESSON_ID=2593), [PHP short_open_tag](https://www.php.net/manual/en/ini.core.php#ini.short-open-tag), [исследование установщика](bitrix-install-research.md).

PHP 8.3.35 необходимо проверить на фактическом образе и в FPM: официальный минимум PHP 8.2, рекомендуемый актуальный PHP выше; MySQL требуется 8.0+, UTF-8/`utf8mb4`. Версия, расширения и успешный CLI `php -m` не заменяют проверку веб-мастера. [Требования продукта](https://www.1c-bitrix.ru/products/cms/requirements.php).

`bitrix.ini` **не переопределяет** `auto_prepend_file`, `disable_functions`, `allow_url_fopen`, `allow_url_include`, `sendmail_path`, параметры почты или сессии, память и временные/размерные лимиты `demo.ini`. Сохраняются 512 MiB, 60 секунд PHP, upload 32 MiB и POST 36 MiB; FastCGI ожидает ответ до 65 секунд без данных. Более высокие рекомендации вендора для больших файлов/долгих операций не объявляются выполненными. Если конкретный шаг требует изменения лимита, сохранить точную ошибку и обосновать отдельную конечную величину; не отключать изоляцию. `max_file_uploads=100` ограничен теми же общими 36 MiB POST.

## Приёмка на фактическом контейнере

Локально выполнено: Windows PHP 8.3.35 с `-c infra/provisioning/bitrix.ini -r` подтвердил семь доступных CLI параметров (`1`, `UTF-8`, `10000`, `100`, `1000000`, `14000`, `4096k`); переданный через stdin инертный `<? echo "SHORT_TAG_OK"; ?>` выдал `SHORT_TAG_OK`. `cgi.fix_pathinfo` в этой CLI-сборке недоступен (`ini_get` вернул `false`), поэтому его проверка отнесена к целевому FPM. Node + PHP PCRE из фактического конфига: **32/32 PASS** (5 допустимых статических путей и 27 отказов), пять точных постоянных `SCRIPT_FILENAME`/`REQUEST_URI`/`HTTP_HOST` — PASS; восемь новых INI-настроек не пересекаются с ключами `demo.ini` — PASS. Это проверка содержимого/PCRE и локального PHP, **не `nginx -t` и не HTTP-проверка**. Первый запуск статического checker завершился ошибкой его разбора однострочного rewrite; после исправления checker матрица прошла, профиль из-за этого не менялся.

После подтверждённых root дополнений повторный Node + PHP PCRE checker: **38/38 PASS** (7 допустимых статических путей, включая оба exact JS, и 31 отказ, включая соседние пути внутри modules). Проверка пяти наборов FastCGI: параметры уникальны, `HTTPS`/`SERVER_PORT`/`REQUEST_SCHEME` единообразны, raw URI/Host/query и постоянные пути сохранены — **5/5 PASS**. Статическая модель фактически записанной map: **8/8 PASS** для доверенного HTTPS, HTTP, чужого peer, loopback, пустого заголовка, смешанного `https, http` и допустимого регистра `HTTPS`. Последняя проверка не является сетевым probe. Независимый read-only review обновления не выявил блокирующих замечаний; реальные TLS/FPM assertions выполняет root.

Последнее дополнение после чтения root `legal/license.php`: итоговый повтор — **41/41 PASS** для статических/запрещённых путей, **6/6 PASS** для уникальных CGI-наборов, **2/2 PASS** для exact JS GET, **1/1 PASS** для ограничения legal endpoint GET/HEAD и **8/8 PASS** для статической модели HTTPS map. Новые отрицательные случаи: соседний `/bitrix/legal/other.php`, `/bitrix/legal/license.php/test` и прямой `/bitrix/legal/license.html`. Лицензионное соглашение не принималось; результаты HTTP/FPM и отображение его iframe проверяются root отдельно на фактическом runtime.

Эти проверки выполняет исполнитель сервера перед мастером и сохраняет только очищенные результаты; в данной задаче серверные проверки **NOT_RUN**.

1. `nginx -t` с реально смонтированным профилем и живым DNS имени `php`; `php --ini` и точечный вывод `ini_get` только несекретных параметров выше, плюс значения изоляции. Проверить PHP/FPM, short-tag inert probe, mysqli/mbstring/opcache и prepend без чтения файла лицензии.
2. Без пароля `/`, `/index.php`, существующий CSS и каждый разрешённый admin endpoint должны вернуть 401 до выполнения PHP. Не проверять Basic Auth через `return 200` в Nginx: rewrite-ответ выполняется до auth phase. Несуществующий/запрещённый путь может сразу вернуть 404.
3. С Basic Auth проверить работу мастера и существующих статических ресурсов, включая `.default` и оба exact JS; POST к статике не допускается. Неприсутствующий разрешённый PHP должен вернуть 404, никогда исходный текст. В инертном тестовом корне подтвердить, что FastCGI получил исходный `REQUEST_URI` с повторяющимися query и `HTTP_HOST` с портом, а через подтверждённый host TLS ingress — `HTTPS=on`, `SERVER_PORT=443`, `REQUEST_SCHEME=https`. С другого peer поддельный `X-Forwarded-Proto: https` не должен включать HTTPS или менять порт 8080. Не создавать PHP probe в лицензированном корне.
4. Отрицательные запросы, в том числе с `--path-as-is`: `/bitrix/license_key.php`, `/bitrix/license_key.php.css`, `/bitrix/.settings.php`, `/bitrix/.settings_extra.php`, `/bitrix/php_interface/dbconn.php`, `/bitrix/backup/test.zip`, `/index.php/path`, `/bitrix/tools/anything.php`, `/upload/test.php`, `/.git/config`, `/bitrix/js/.env.css`, `/bitrix/js/test.sql.css`, `/bitrix/js/test.php/image.jpg`. Ожидается 404 без содержимого файлов и без запуска PHP. Повторить с закодированными точками и проверить отсутствие traversal; не читать настоящий ключ ради сравнения ответа.
5. Подтвердить отсутствие access-log записей запросов мастера, noindex/no-store на 200/401/404 и отсутствие внешних почтовых, DNS, HTTPS и фоновых действий. Запреты не ослаблять ради зелёных проверок CMS.
6. После создания администратора закончить минимальную установку без решения, зафиксировать версию/редакцию/состояние лицензии без секрета. Удаление/замена корневого установщика — после отдельного snapshot по runbook; вернуть mount профиля `demo.conf`, отключить installer override, выполнить `nginx -t` и проверить, что корневой мастер более недоступен. `20-upgrade-bitrix.ini` допустимо сохранить как платформенную настройку при обязательном последующем `zz-upgrade-demo.ini`.

Семантика Nginx проверяется по [приоритету exact/regex locations и исходному request URI](https://nginx.org/en/docs/http/ngx_http_core_module.html#location), [FastCGI-параметрам](https://nginx.org/en/docs/http/ngx_http_fastcgi_module.html#fastcgi_param) и [map из нескольких исходных переменных](https://nginx.org/en/docs/http/ngx_http_map_module.html). Фактическая установка, активация, штатные проверки Битрикс и `DEMO_READY` этим изменением не заявляются.
